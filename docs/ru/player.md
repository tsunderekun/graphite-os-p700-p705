# PLAYER-FEATURES — функционал плеера LG P700

> Публичный технический план. Пометки **[проверить]** означают, что оценка
> требует замера; пути данных обозначены плейсхолдерами.

> Составлено 24.11.2026 по фактам, снятым с телефона (read-only): MPD 0.24.20,
> `/etc/mpd.conf`, `mpc`, `idle`, `readpicture`, `evtest`, `/proc`. Код не менялся,
> настройки MPD не трогались, воспроизведение в ходе аудита не запускалось.
> Там, где вывод сделан по возможностям MPD, а не по замеру, стоит **[проверить]**.

Документ отвечает на вопрос «что должен уметь плеер и в каком порядке это делать».
Текущее состояние железа и системы — `PLAYER-STATUS.md`, `SYSTEM-STATUS.md`,
дизайн — `notes/shell/DESIGN-SYSTEM.md` / `SCREENS.md`.

## 0. Коротко

1. **Бэкенд уже есть и он полноценный.** MPD 0.24.20 умеет всё, что нужно
   плееру: `idle`, фильтры и поиск, `readpicture`, плейлисты, очередь с
   позициями, `random/repeat/single/consume/crossfade/replay_gain_mode`,
   партиции. Не хватает только **stickers** (база отключена) и **скорости
   воспроизведения** (команды нет вовсе). Значит, вся работа — клиентская.
2. **Главный дефицит — не функции, а бюджет 1 ГГц / 400 МБ / тач с опросом
   ~200 мс.** Поэтому библиотека строится один раз в компактный индекс на диске,
   обложки декодируются вне UI-потока и кэшируются, а обновление экрана идёт по
   `idle`, а не опросом.
3. **Сейчас плеер выглядит беднее, чем может, из-за трёх конкретных вещей:**
   обложки из тегов не показываются вообще (`albumart` вместо `readpicture`),
   состояние тянется двумя запросами раз в секунду вместо `idle`, а очередь
   перечитывается целиком. Это чинится в P0 и даёт больше «ощущения плеера»,
   чем любая новая фича.

## 1. Что есть сейчас и что проверено

### 1.1. Текущий плеер (`notes/lp7player.cpp`, ~1,5 тыс. строк)

- Экраны: «Сейчас», «Очередь», «Инфо», «Настройки», лок, подтверждение питания.
- MPD: один TCP-сокет, `status` + `currentsong` раз в секунду, `playlistinfo`
  при открытии очереди, `albumart` + чтение `cover.jpg` с SD, `seekcur`,
  `setvol ±5`, `random`/`repeat` как два независимых тумблера.
- Обложка декодируется **синхронно в UI-потоке** при смене трека.
- Настройки: `<system-settings>` (`theme`, `btnlight`), запись неатомарная.
- Клавиши: `event1` (Vol±, Home), `event5` (Vol±, Power), удержание Vol ≥0,7 с —
  next/prev.

### 1.4. Что из этого следует

- Источник правды — MPD. Клиент не хранит очередь, режимы и громкость у себя:
  он их читает из `status` и меняет командами.
- Полноценная библиотека **не запрашивается у MPD на каждый экран**: один
  проход `listallinfo` → компактный индекс на диске → мгновенные списки.
- Обложки берутся из `readpicture` (встроенные), затем `cover.jpg`/`folder.jpg`
  из каталога файла; `albumart` не использовать.
- Пользовательский поиск — только `search`/`searchcount`/`searchadd`
  (регистронезависимые). `find` — для точного равенства тега.
- Позиция в треке и «продолжить слушать» — наша зона: MPD её не помнит.

## 2. Архитектура клиента

### 2.1. Два сокета MPD

```
control  — команды и короткие ответы (таймаут 1 с, переподключение)
idle     — только idle/noidle, читается в select(), переподключается отдельно
```

Почему два: на одном соединении нельзя одновременно ждать `idle` и слать
команды. Сейчас в коде один `Mpd` и `cmd()` рвёт соединение при любой ошибке —
после перехода на idle это станет заметно.

Правила:
- `connect` → прочитать приветствие → `binarylimit 1048576` (иначе обложки
  приходят по 8 КБ) → `idle player mixer options playlist database
  stored_playlist output update`.
- Пришло событие → разобрать строки `changed: X` до `OK` → обновить нужное →
  **сразу переотправить `idle`**.
- Обрыв (recv ≤ 0) → закрыть, backoff 1→2→5→10 с, при переподключении сбросить
  кэш очереди и перечитать `status`, `currentsong`, режимы.
- Пока играет, позиция экстраполируется локально от `elapsed` + `CLOCK_MONOTONIC`
  и сверяется `status` раз в 5 с (0,5 мс — дёшево). Прогресс-линия
  перерисовывается 1 раз в секунду, но без запросов к MPD.
- Если `idle` не поддержан (ACK) — деградация до опроса 1 с, без падения.

### 2.2. Индекс библиотеки

Один проход `listallinfo` (или по каталогам, если библиотека огромная — см.
§6.4) → разбор → **текстовый кэш** `<player-data>/index.txt`:

```
#v1 <db_update> <songs> <albums> <artists>
A<TAB>album_id<TAB>Album<TAB>AlbumArtist<TAB>year<TAB>discs<TAB>tracks<TAB>duration
R<TAB>artist_id<TAB>Artist<TAB>albums<TAB>tracks
T<TAB>uri<TAB>title<TAB>artist_id<TAB>album_id<TAB>genre<TAB>year<TAB>track<TAB>disc<TAB>sec
```

- Ключ альбома — `(AlbumArtist || Artist, Album)`, для сборников
  (`AlbumArtist` = «Various Artists») — только `Album`.
- `db_update` из `stats` — версия кэша. Совпала — читаем файл (5 тыс. строк
  ≈ 600 КБ, разбор ~30 мс). Не совпала — перестраиваем в фоне.
- Перестройка — в отдельном потоке; UI показывает «Обновление библиотеки…»,
  список остаётся доступен по старому индексу.
- Пустые теги: нет `Album` → «Без альбома», нет `Artist` → «Неизвестный
  исполнитель», нет `Title` → имя файла без расширения и номера.
- Индекс нужен только для списков; воспроизведение и очередь работают и без него.

### 2.3. Обложки

```
1) readpicture(uri, 0)            — встроенная (после binarylimit)
2) <dir>/cover.jpg|folder.jpg|front.jpg|albumart.jpg  — файл рядом с треком
3) заглушка ♪ / «НЕТ ОБЛОЖКИ»
```

- Декодирование — **в фоновом потоке**, UI сначала рисует заглушку и приходит
  к обложке, когда готово. Синхронный `stbi_load` на 300 КБ JPEG блокирует
  интерфейс на сотни миллисекунд — сейчас так и происходит.
- Кэш тамбнейлов: `<player-data>/art/<hash>.565`, 96×96 RGB565 = 18 КБ.
  500 альбомов ≈ 9 МБ на rootfs (не на SD: карту вынимают).
- Большая обложка 384×384 не кэшируется на диск, но держится в RAM для
  текущего альбома (≈290 КБ RGB565) и декодируется один раз на альбом, а не на
  трек.
- Загрузка — ленивая: только видимые строки, по одной, с приоритетом текущей.
  Массовая предзагрузка 300 альбомов = минуты CPU на 1 ГГц, так делать нельзя.
- Ограничение кэша — 30 МБ, вытеснение по LRU, кнопка «Очистить» в настройках.

### 2.4. Файлы состояния

| Путь | Что | Размер |
|---|---|---|
| `<player-data>/index.txt` | индекс библиотеки | 0,5–1 МБ на 5 тыс. треков |
| `<player-data>/art/*.565` | тамбнейлы | до 30 МБ |
| `<player-data>/played.log` | история прослушивания (uri, ts) | ротация 2000 строк |
| `<player-data>/bookmarks` | uri → секунда (аудиокниги) | единицы КБ |
| `<player-data>/lastpos` | uri + elapsed каждые 15 с | <1 КБ |
| `<system-settings>` | тема, подсветка, предпочтения плеера | <1 КБ |

Запись настроек и закладок — атомарно (tmp + `rename`), иначе выключение по
питанию оставит обрезанный файл.

## 4. Объём первого релиза (P0)

### 4.1. Входит

1. **MPD-слой**: два сокета, `idle` c переотправкой, backoff, `binarylimit`,
   операции по `Id`, инкрементальная очередь через `plchangesposid`.
2. **Обложки**: `readpicture` → файл рядом → заглушка; декод в фоне; дисковый
   кэш 96×96; кэш текущего альбома в RAM.
3. **Индекс библиотеки** + дисковый кэш, инвалидация по `stats.db_update`,
   фоновая перестройка.
4. **Экраны**: «Библиотека» (Альбомы / Исполнители / Песни), «Альбом»,
   «Исполнитель»; действия «Слушать», «В очередь», «Следующим»; шторка
   действий по долгому нажатию.
5. **Очередь**: «следующим», «в очередь», удалить, очистить, «⋯»-меню,
   корректный текущий по `id`, 100+ треков.
6. **Режимы**: shuffle + repeat off/all/one с честной индикацией.
7. **Resume**: проверить `state_file`; свой `lastpos` для секунды; настройка.
8. **Состояния и ошибки**: MPD недоступен, пустая очередь/библиотека, нет SD,
   битый файл, нет обложки.
9. **Старт**: ждать MPD до 10 с, не считать это ошибкой; не пытаться поднимать
   MPD из UI.

Оценка: **~18–22 дня** одним разработчиком. Если нужно уложиться в две недели,
режем: «Исполнители» (−1,5 дня), дисковый кэш обложек (−1), «Следующим» (−1) —
но тогда плеер перестаёт быть «полноценным».

### 4.2. Не входит (сознательно)

| Что | Почему |
|---|---|
| Поиск | нужна экранная клавиатура; в fb-плеере её нет, в шелле — есть. P1 вместе с клавиатурой |
| Плейлисты и избранное | нужен ввод имени и список; P1 сразу после P0 |
| Таймер сна | не влияет на «слушать музыку»; P1 |
| Кнопка гарнитуры | P1, проверяется одним `evtest` |
| Crossfade | CPU 1 ГГц, два декодера; риск заикания. P2 после замеров |
| ReplayGain | мало файлов с тегами; P2 |
| Жанры, часто игранное, сетка альбомов, drag-reorder | P2 |
| Папки, «недавно», сортировки, алфавит | P1, сразу после P0 — не влияют на базовый сценарий |
| Эквалайзер | AUDPP не разобран, шум в тестах (`EQ-STATUS.md`) |
| Скорость воспроизведения | **MPD не умеет** — команды нет в `commands` |
| Last.fm | нет сети и учётки; только локальный `played.log` |
| BT-выход | A2DP не работает |
| Сетка альбомов, drag-reorder | P2, после того как список докажет удобство |

### 4.3. Порядок работ

```
1. MPD-слой (idle, переподключение, ids)       3 дня
2. Обложки (readpicture, фон, кэш)             3 дня
3. Индекс библиотеки + кэш                     5 дней
4. Библиотека: альбомы/исполнители/песни       5 дней
5. Очередь: следующий/удалить/очистить         2 дня
6. Режимы + resume                             2 дня
7. Состояния/ошибки + приёмка                  2 дня
```

Каждый шаг заканчивается работающим экраном — не «сначала всё, потом UI».

## 6. Технические заметки

### 6.1. Команды MPD, которые нужны

| Задача | Команда |
|---|---|
| состояние | `status`, `currentsong` |
| очередь | `playlistinfo [start:end]`, `plchangesposid <ver>` |
| играть | `play <pos>`, `playid <id>`, `pause 0/1`, `next`, `previous`, `stop` |
| перемотка | `seekcur <сек>`, `seekid <id> <сек>` |
| добавить | `add <uri>`, `addid <uri> [pos]`, `findadd`, `searchadd` |
| убрать/двинуть | `delete <pos>`, `deleteid <id>`, `move`, `moveid`, `swap`, `shuffle` |
| очистить | `clear` |
| режимы | `random`, `repeat`, `single`, `consume`, `crossfade`, `replay_gain_mode` |
| громкость | `setvol <0..100>`, `getvol` |
| библиотека | `lsinfo`, `listallinfo`, `list <Tag>`, `find "(…)"`, `search`, `searchcount`, `stats`, `update`, `rescan` |
| обложки | `binarylimit <n>`, `readpicture <uri> <offset>` |
| плейлисты | `save`, `load`, `listplaylists`, `listplaylist`, `listplaylistinfo`, `playlistadd`, `playlistdelete`, `playlistmove`, `playlistclear`, `rename`, `rm` |
| события | `idle [player mixer options playlist database stored_playlist output update]`, `noidle`, `ping` |

Все аргументы-строки экранировать: `\` → `\\`, `"` → `\"`. Пакетные
операции — `command_list_begin` / `command_list_ok_begin` (один round-trip).

### 6.2. `idle`

Подписки и реакция:

| Событие | Что делаем |
|---|---|
| `player` | `status` + `currentsong`; смена трека → обложка, `played.log`, `lastpos` |
| `mixer` | обновить `VOL N%` (железные кнопки) |
| `options` | shuffle/repeat/crossfade/RG/consume |
| `playlist` | очередь изменилась → `plchangesposid` |
| `database` / `update` | перестроить индекс (debounce 2 с), снять «Обновление…» |
| `stored_playlist` | перечитать плейлисты |
| `output` | `outputs` (пока один) |

- `idle` не отваливается по `connection_timeout` — это документировано и
  проверено.
- Пока идёт `idle`, на этом сокете нельзя слать команды, только `noidle`.
- Событий «прошла секунда» нет: прогресс считаем сами.
- Если соединение зависло (нет данных и нет событий > 30 с при играющем
  статусе) — `ping`; нет ответа → переподключение.

### 6.3. Очередь

- Позиция в очереди меняется от `random`/`shuffle`/`move` → **всегда
  адресуем по `id`** (`playid`, `deleteid`, `moveid`), позиция — только для
  отрисовки.
- `status.playlist` — версия очереди. `plchangesposid <ver>` возвращает только
  изменившиеся `cpos`/`Id`; метаданные для них берём `playlistinfo pos:pos+1`
  или из локального кэша, если uri уже известен.
- «Следующим» = `addid <uri> <song+1>`; для stopped — позиция = конец.
- «Играть всё» = `clear` + `add` (или `findadd`) + `play 0`; лучше пакетной
  командой, чтобы UI не увидел промежуточную пустую очередь.
- `max_playlist_length` по умолчанию 16 384 — для «в очередь всю библиотеку»
  проверять `playlistlength` и предупреждать.

### 6.4. Библиотека и большие объёмы

- `listallinfo` на 5 тыс. треков ≈ 1,5–2,5 МБ и 0,3–0,8 с (экстраполяция от
  23 строк/20 мс; **[проверить]** на реальной библиотеке).
- Ограничение `max_output_buffer_size` = 8 МБ: на ~25 тыс. треков один ответ
  может не влезть. Тогда обходить по каталогам: `lsinfo ""` → для каждого
  каталога `lsinfo "<dir>"`, объединяя результат.
- `search` — линейный проход по БД в памяти: 5 тыс. треков ≈ 10–30 мс
  (**проверить**), 50 тыс. — уже сотни мс, поэтому debounce и лимит.
- `find` с `contains`/`=~` **регистрозависим** (проверено): для UI-поиска не
  годится, только для точных равенств (`Album == "…"`, `Genre == "…"`).
- Память MPD: 11,4 МБ RSS при 2 треках (в основном код и библиотеки).
  На 5 тыс. ожидаемо 15–25 МБ (**проверить**). При 10 тыс.+ стоит включить
  `metadata_to_use` (убрать Composer, Mood, MusicBrainz*), это экономит и RAM,
  и трафик. **Конфиг не трогаем без согласования.**

### 6.5. Теги и группировка

- Альбом: `AlbumArtist` (fallback `Artist`) + `Album`. Для сборников
  (`AlbumArtist` = Various Artists) — только `Album`.
- `Track` бывает `3` и `3/12` → берём число до `/`.
- `Date` бывает `2023`, `2023-12-19` → год = первые 4 цифры.
- `Disc` — сортировка disc→track; без тега — disc 1.
- Пустые значения MPD отдаёт как пустую строку, а не отсутствие ключа:
  различать «нет тега» и «пустой тег» не нужно, оба → подстановка.
- Кодировка: MPD отдаёт UTF-8 (проверено на кириллице). Если в файле был
  cp1251 и тег не сконвертирован — увидим «кракозябры»; автоматически не
  лечим, показываем как есть. В UI — безопасная замена невалидных
  последовательностей на «?», без падений.
- Шрифт DejaVu покрывает кириллицу и латиницу; CJK/эмодзи будут «тофу» —
  это ограничение шрифта, не плеера.

### 6.6. Плейлисты и избранное

- Плейлисты MPD — это файлы `.m3u` в `<mpd-data>/playlists`; имя = имя
  файла. Запрещены `/` и управляющие символы, длина ограничена.
- **Stickers недоступны**: `sticker database is disabled`, в `mpd.conf` нет
  `sticker_file`. SQLite в MPD слинкован, то есть включить можно одной строкой
  + перезапуск, но это изменение конфига и лишняя запись в БД на каждый лайк.
- Поэтому «Избранное» — **обычный плейлист** с ASCII-именем `Favorites`
  (в UI — «Избранное»). Проверка «уже в избранном» — кэш `listplaylist
  Favorites` (обновляется по событию `stored_playlist`).
- `playlistdelete` работает по позиции, а не по uri → позицию берём из кэша.
- Если позже понадобятся рейтинги/«проиграно N раз» на трек — тогда и только
  тогда включать `sticker_file` (и это будет P2, с миграцией).

### 6.7. Режимы и звук

| Что | Как | Нюанс |
|---|---|---|
| shuffle | `random 1` | очередь визуально **не** переставляется, меняется только выбор следующего |
| repeat off | `repeat 0`, `single 0` | |
| repeat all | `repeat 1`, `single 0` | |
| repeat one | `repeat 1`, `single 1` | `single oneshot` (0.24) — остановиться после текущего |
| gapless | автоматически | только при одинаковом формате; при разном — щель ~100–300 мс |
| crossfade | `crossfade N` | только одинаковый формат, два декодера → CPU. **Не включать по умолчанию** |
| ReplayGain | `replay_gain_mode track/album/auto` | нужны теги; при `album` — по альбому; без тегов не применяется |
| громкость | software (`mixer_type software`) | аппаратный `PCM Playback Volume` есть, но ioctl даёт EPERM; ниже ~10 % слышна потеря разрядности — предупреждать не нужно, но ползунок в шторке не должен уходить в 1–2 % |
| нормализация | `volume_normalization` только в конфиге и только 16 бит | не используем, есть ReplayGain |

### 6.8. Resume, закладки, таймер сна

- **Resume on boot**: `state_file` восстанавливает очередь, текущий трек,
  режимы и громкость, но **не секунду внутри трека** (проверено по содержимому
  `state`). Свой `lastpos` (`uri`, `elapsed`) пишем каждые 15 с при
  воспроизведении и на pause/stop; после старта, если трек совпал и настройка
  включена, делаем `seekcur (elapsed-3)`. Проверить, что `seekcur` сразу после
  `play` не даёт ACK.
- `state_file_interval` по умолчанию 120 с: при жёстком выключении теряется до
  двух минут изменений очереди. Уменьшить до 15–30 с — одна строка в конфиге.
- **Закладки (аудиокниги)**: `<player-data>/bookmarks`, ключ — uri,
  значение — секунда и время. Для файлов >20 мин при открытии показываем
  «Продолжить с 12:34 / С начала»; авто-резюм — только при включённой
  настройке, иначе можно случайно прыгнуть в середину.
- **Таймер сна**: дедлайн в памяти; по истечении — плавно `setvol` шагами по
  5 % за 100 мс до 0, `pause`, вернуть громкость, погасить экран. Пока идёт
  таймер, в настройках показываем остаток; на локе — «СОН 12 МИН» 11 dim.
- Скорость воспроизведения: **не поддерживается** (`commands` MPD не содержит
  `speed`), альтернатив на этом железе нет. В UI не обещать.

### 6.9. Кириллица, сортировка, поиск

- Порядок `list` задаёт MPD (ICU/байтовый — русскую азбуку он не гарантирует:
  «Ё» может встать после «Я»). Поэтому списки сортируем сами: casefold + карта
  `ё→е`, `й→и` для ключа сортировки, исходная строка — для отображения.
- Поиск — `search` (ICU, регистронезависим, проверено). Запрос экранируется,
  минимум 2 символа, `%`/`_` не спецсимволы (это не SQL).
- Транслит не делаем: ICU и так находит «гранж» по «Гранж».

## 9. Риски

1. **1 ГГц и JPEG.** Декод 300-КБ обложки на UI-потоке — гарантированные
   рывки. Лечится фоном и кэшем; если и в фоне медленно — преддекодировать
   следующий трек заранее.
2. **Память на большой библиотеке.** MPD + индекс + кэш обложек в 400 МБ
   помещаются до ~10 тыс. треков; дальше — `metadata_to_use`, лимит кэша,
   отказ от предзагрузки.
3. **Параллельный переезд в X.** Логика (MPD, индекс, обложки, настройки)
   должна жить в отдельном слое, иначе её напишут дважды — для fb и для шелла.
   Это главный архитектурный риск проекта, а не фичи.
4. **Тач.** Резистивный экран, опрос ~200 мс, нет мультитача: долгое нажатие
   против скролла, никаких свайпов по строкам, зоны ≥44 px.
5. **SD и vfat.** Нет прав/владельцев, регистронезависимость, длинные имена,
   Unicode NFC/NFD — сравнивать uri побайтово, не нормализовать.
6. **MPD без SD.** `mpd.start` молча выходит, если нет `/media/sd/Music` →
   «MPD недоступен» на пустом месте. Нужен ретрай/супервизор и понятный текст.
7. **Питание.** Неатомарная запись настроек и `state_file_interval` 120 с.
8. **Обещания.** BT, GPS, скорость, Last.fm, EQ — не показывать в UI, пока не
   работает.

## 10. Три главных вывода

1. **Всё, что нужно от бэкенда, уже есть.** MPD 0.24.20 на телефоне умеет
   `idle` (4 мс), регистронезависимый поиск по кириллице, `readpicture`,
   плейлисты, очередь по id, `random/repeat/single/crossfade/replay_gain`.
   Единственные настоящие дыры — stickers (отключены конфигом), скорость
   (нет в MPD) и BT. Поэтому «плеер» — это клиентская работа, и её видимый
   эффект зависит от трёх вещей: индекса, обложек и реактивности.
2. **Библиотека — это индекс, а не запросы.** На 1 ГГц нельзя дёргать MPD на
   каждый экран и нельзя декодировать обложки в UI-потоке. Один проход
   `listallinfo` → файл-кэш, ленивые тамбнейлы 96×96 на диске, фоновая
   перестройка по `db_update`. Это же снимает вопрос «тысячи треков».
3. **Сейчас плеер проигрывает не по функциям, а по ощущению.** Встроенные
   обложки не видны вообще (`albumart` вместо `readpicture`), UI обновляется
   опросом раз в секунду, очередь перечитывается целиком. Починка этих трёх
   вещей + честные пустые состояния дадут больше, чем поиск или эквалайзер.
